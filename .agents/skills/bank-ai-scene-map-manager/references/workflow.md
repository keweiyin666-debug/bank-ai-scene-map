# 银行 AI 场景地图管理工作流

维护入口：先读00/16号规则。落实部门唯一源为`data/department-mapping.json`，行级使用对象唯一源为`data/organization-audiences.json`；修改获批关系后运行`rtk proxy node scripts/scene-library/refresh-departments.mjs`，再构建、三项回归、迁移前快照及三项同步。v0.8.0支持schema1/2/3；先部署兼容页面，再发布schema3。导航为“按组织｜按业务域”，组织分列行级管理和业务/职能部门，L2由逐卡关系派生，不能将领导岗位当部门或把整个场景群默认提升为行级。GitHub公开归档由`package-project.mjs <checkout>`生成，根HTML继续作为Pages入口；不把本地原件、内部客户映射或共享覆盖快照加入仓库。公开源卡为审核投影，证据回收仍以本地完整源卡为准。

## 1. 材料入库

Knowhow 方案链接发现与补全是提炼流程的固定步骤，执行 [knowhow-asset-enrichment.md](knowhow-asset-enrichment.md)。仅补现有卡的共享链接时无需重发 HTML 或完整目录；新增/修改正式业务内容仍按三项同步协议执行。

1. 记录材料名称、客户或项目、日期和适用范围。
2. 提取四类信息：已确认事实、客户观点、顾问判断、待验证假设。
3. 对每条候选内容回答：
   - 属于哪个 L1？
   - 发生在哪个 L2？
   - 能否直接形成稳定、独立的 L4？
   - 是否确有必要建立统领多个 L4 的 L3 场景群？
   - 哪个标准银行部门主责、哪些部门协同？实际使用者是否为外部客户？关系依据、适用条件和审核状态是什么？
4. 先与现有 L4 比较主要使用人/组织和实际业务需求；两者基本一致时视为同一场景，再把输出、客户、渠道和实现方式记录为变体。
5. 候选先进入独立审核区，提交来源、归并判断与差异；用户确认指定版本和范围后，才更新独立 L4 文档、L1—L4 源台账及变更记录。批量策略见 [batch-ingestion.md](batch-ingestion.md)。

部门与业务域是同一场景集合的两个组织视角。提炼与归类时读取项目16号规则，直接按L4登记主责/协同，再自动汇总L2/可选L3；不能整域套用部门，不能把建设方当主责。关系未确认不造事实、不进入正式部门导航，场景仍保留全库及业务视图访问。存量补录只补审受影响关系，不默认重做全部业务提炼。

## 2. L3 场景群提炼

只有同时满足“至少两个 L4、共同业务目标、对外需要整体介绍、名称不与 L2/L4 重复”时才建立 L3。每个 L3 至少形成：

- 场景方向名称；
- 45—90 个汉字的页面摘要；
- 所属 L2；
- 主使用角色；
- 是否王牌场景；
- 成熟度和页面状态；
- 至少两个已登记 L4。

摘要句式优先采用：

```text
面向【角色】，围绕【业务对象/流程】完成【主要工作】，支持【业务价值】。
```

句式只是检查工具，不要求机械套用。

## 3. L4 场景提炼

L4 必须能回答：

- 谁使用；
- 哪个银行部门主责、哪些部门协同，依据和适用条件是什么；使用岗位与外部服务对象分别是谁；
- 什么时点触发；
- 要完成什么业务任务；
- 使用哪些数据范围；
- 输出什么业务产物；
- AI 参与到什么程度；
- 谁确认结果；
- 是否由外部 Agent 发起；
- 是否调用资产网关；
- 当前能力边界是什么；
- D01—D04 当前分别覆盖到什么程度；
- AI 决策参与等级是 AI-L1、AI-L2 还是 AI-L3；
- 当前实现范围和场景版本是什么；
- 是否已有方案 PPT、看板 Demo、Dora 体验或短视频。
- 当前有哪些实现路径：BI、AI、联合 Agent，可多选；默认 BI 基础不等于已经具备 AI 能力。

每个 L4 还必须形成可直接发布的卡片字段：

- Before：当前角色、作业方式、主要耗时或断点；
- After：已实现的新作业方式与仍由人工承担的责任；仅为建议的 Dora/AI 增强必须分开标注，不能将 BI 实践改写为 AI 上线事实；
- 用户反馈：第一人称一句话预期体验；
- 效率价值：指标性质、基线、目标值、统计周期和适用范围；
- 质量/风险价值：指标性质、基线、目标值、统计周期和适用范围；
- 经营/管理价值：指标性质、基线、目标值、统计周期和适用范围。

指标性质只能使用 V00—V04。材料没有可靠数字时写“V00 待确认量化目标”，列出需要补充的基线或口径，不根据相似项目自行估算。V01 申报目标、V02 建议试点目标和 V03 实测参考不得改写为已实现结果。

使用 C03 联合 Agent 时补充：主 Agent、Dora 子任务、资产网关能力、返回产物、权限和人工确认点。

资产网关只在历史 BI 资产依赖度高时标记。判断重点是是否需要发现、定位、复用或追溯既有报表、看板和数据集，而不是场景是否使用数据。

## 4. HTML 场景卡片发布

涉及场景填充、页面摘要或 HTML 更新时，先读取 `银行AI场景地图内容库/07_场景卡片HTML发布体系.md`。

1. 先在 `04_L4_具体场景.md` 完成业务字段，不直接在 HTML 中创造事实；
2. 确认页面状态。只有“发布”或用户明确允许进入原型的候选场景可以进入 HTML；
3. 将 L4 字段映射为场景对象，保持 `id`、`title`、`definition`、`decision`、`abilities`、`maturity`、`version`、`flagship`、`benchmark`、`digitalTalent`、`gateway`、`values`、`role`、`trigger`、`task`、`dataScope`、`outputs`、`collaboration`、`manualCheck`、`before`、`after`、`feedback`、`metrics`、`quantBasis`、`scope`、`boundary` 和 `assets` 数据契约；
4. L1、L2 和可选 L3 通过 `domains[].sections[]` 维护，不在 L4 对象中重复；
5. 主卡片固定发布场景名称与定义、Before、After、用户反馈和三项核心价值；量化指标只在 Markdown 内容库治理，不在页面卡片展示；
6. 详情抽屉固定使用场景概览、Before / After、能力深度、业务价值、资产与边界五个页签；
7. 普通内容更新不得顺带改变组件结构、视觉体系和交互。页面改版必须来自用户明确要求，并同步升级发布体系版本。
8. 正式新增按用户2026-10-21常设要求，读取15号协议，同批更新14号流水线、HTML与原Supabase完整目录；先核对源卡再维护发布JSON，统一构建，保留既有共享覆盖与revision。盘点及未获批候选不触发发布；用户明确限定仅本地或暂不发布时从其限定。
9. 双视角实施遵循16号计划：部门入口在前且默认，业务域模式保留，两种组织方式共用L4及共享编辑；部门关系是经审核的目录数据，不扩大访客编辑权限。当前v1目录严格限制字段，结构扩展须兼容升级，不直接把计划字段塞进旧载荷。规则文档更新本身不触发发布或标记页面已完成。

`candidate()` 只用于候选占位。正式填充场景时，不能把默认 Before、After、用户反馈、价值或资产状态当作材料事实。

## 5. 去重判断

### 场景身份判定

- 第一判断是主要使用人/组织是否基本一致；
- 第二判断是实际业务需求是否基本一致；
- 两者基本一致时认定为同一 L4，并通过来源、版本、实现路径和案例记录差异；
- 输出结果用于辅助核验，不作为高于“使用人/组织 + 实际业务需求”的独立拆分标准。

### 优先合并

- 主要使用人/组织基本一致；
- 实际业务需求基本一致；
- 仅客户、产品、渠道、报表、数据来源、输出样式或发起入口不同；
- 仅 BI、AI、联合 Agent 或具体工具不同。

### 可以拆分

- 业务责任主体明显不同，且对应的职责、权限或动作不同；
- 实际业务需求不同，即使复用了相同数据、看板或模型；
- 触发时点、流程位置或人工责任边界的差异，已经使业务需求发生实质变化。

### 作为内部模块

- 指标专题；
- 单个产品或客群；
- 到期、流失、授信未用等分析主题；
- 报告的章节或图表；
- 王牌场景中的实施模块。

## 6. 发布前校验

### 结构

- L1、L2、L3、L4 编码唯一；
- L4 必须追溯到 L2 和 L1；有 L3 时同时校验 L3 引用；
- 页面状态为“发布”的 L3 至少有两个 L4；
- 王牌场景仍归属于一个正式 L1 和 L2。
- 每个新候选同时完成部门分析；已确认关系的部门/L4引用、主责边界、依据性质和审核记录有效，待确认项单列；不同部门重复引用不增加唯一L4数。

### 内容

- 名称使用业务语言；
- 摘要长度适合页面；
- D01—D04 使用合法覆盖状态，且与当前实现范围一致；
- AI 决策参与等级使用 AI-L1—AI-L3；
- 标签来自字典；
- 联合 Agent 和资产网关只在适当层级出现；
- 客户成效、上线状态和成熟度有材料支撑或标记待核实；
- Before 与 After 描述的是作业方式变化，不与价值指标重复；
- 用户反馈为第一人称，且能对应主要使用角色；
- 三个价值维度均有指标性质，V04 有证据来源、范围和周期；

### 页面

- 更新 `06_页面发布摘要.md`；
- 按 `07_场景卡片HTML发布体系.md` 校验字段映射和稳定版页面结构；
- 统计数量由台账计算；
- 双视角上线后默认部门在前，两视图均按稳定L4去重并共享编辑结果；L3局部匹配不能暗示部门负责整个场景群，未映射卡片不从全库或业务视图消失；
- 卡片摘要与源台账一致；
- L4 卡片在主页面直接可见；搜索、筛选、五段式详情抽屉和移动端布局可用；主卡片不混入编码、成熟度或能力标签；
- 用户反馈区域与同页内容栅格保持一致，桌面端抽屉保持半屏覆盖，移动端无横向页面溢出；
- 页面无控制台错误。
- 流水线说明、HTML内置快照和后台目录同一release及指纹；页面实际从后台读取。状态记录区分本地生成、后台应用和GitHub部署，不以SQL文件生成冒充已入库。
- 页面必须通过 HTTP/HTTPS 地址访问，不得把 `file:///` 或本地文件路径作为交付链接；当前共享版地址以 `12_场景库共享发布记录.md` 为准，本地验证 `http://127.0.0.1:8765/bank-ai-scene-map/index.html` 返回 200。
