# Knowhow 方案链接检索与共享回填

用于新卡提炼时发现方案资产，或用户授权后补全现有卡的“方案 PPT”。复用既有场景、来源台账与原 Supabase 共享资产服务，不改变 UI、场景身份、标签、成熟度或其他文案。

## 检索与核对

1. 实时发现 MCP 工具与参数；工具未暴露时可使用用户已配置的 MCP 做标准初始化和只读调用，认证不打印、不写入审计或公开仓库。优先来源映射、已审案例 ID，再用具体任务、同义词检索，不遍历用户全盘。
2. 按稳定源文件 ID 去重；语义库 document_id 与 Knowhow 文件 ID 分开，使用 metadata 的来源映射，不能拼错对象。关键词检索可能分词扩大召回，不把同词命中当业务相关。分页完成或明确记录候选上限、查询时间及权限范围。
3. 读取正文或语义全文，核对主要使用角色、业务任务和产物；只读到元数据时不宣称读完附件。沿用已有审核证据需记录来源与版本。企业 CBS 服务企业客户，不与银行内部财务混用。
4. 先筛业务匹配，再比较相关候选的实时 viewNum。不可用相关性分、下载量或修订号冒充访问量；不知道访问量则单列待核验。记录所选材料、备选及排除理由，只称“本次已核对候选中访问量最高”，检索截断时不声称全平台最高。
5. BI 案例可作为同一任务的实现参考，不能因此声称该卡规划的 AI、预测或 Agent 已上线。仅主题相近、角色错误、缺少关键任务证据时留空。严禁外发、绝密或保密协议材料不用于公开入口回填；其他内部材料只在用户授权范围引用受权限控制的入口，不上传全文或改变访问权限。

## 标题与地址

使用详情中的干净原名，去除搜索高亮 HTML，追加“-帆软内容平台”；遵守原接口显示文字长度（当前120字符）。字段名“方案 PPT”可以承载云文档、PDF或方案包入口，不承诺文件均为PPTX。

优先平台提供的稳定分享地址。当前 MCP 没有分享/剪贴板工具时，可使用已在登录浏览器核验的标准路由 `https://knowhow.fanruan.com/document/{source_file_id}`；记录为“由来源ID生成并核验”，不得声称操作过分享按钮或取得原始复制文本。不填临时下载、cacheKey、附件地址或含认证信息的 URL。

## 保存与验证

- 授权只读提炼时输出候选链接；授权回填时仅补空白“方案 PPT”，已有人工值默认保留。此次批量回填不隐含覆盖既有链接、其他资产或平台发文权限。
- 每条保存前重新 GET 原 `scene_map_assets`，若方案已非空即跳过。合并当前 links 全对象，只新增目标字段，不清空其他键。
- 调用原 `scene_map_save_links` RPC：`p_scene_id`、`p_expected_revision`、`p_links`；revision 来自刚读取的记录。冲突后重读，仍空白才可有限重试；已有人填写则保留。超时先独立读回判断是否已保存，不能盲目重复写。
- 保存原基线和逐条结果到内部批次目录；小批次有限并发，单次请求设超时，结果即时缓存，恢复时按源ID/版本复用缓存，不全量重跑。失败和未检索成功必须区别于“未匹配”。
- 最后独立读回，核对新增链接、原链接及其他资产键；同时检查文案、标签、完整目录未被本批写入改变。抽样验证页面显示文字及 href，失败如实记录。
- 报告每张卡的检索范围、候选与访问量、证据定位、选中或留空原因、实际保存状态；总数区分新增、原有保留、未匹配、待核验和冲突。内部证据、全文、认证及共享快照留本地。

纯共享资产补全由页面实时读取后台，刷新生效，无需重发 HTML 或 catalog；正式新增场景及业务内容更新仍执行流水线、HTML、后台三项同步。规则变更可同步原 GitHub 维护仓库，不携带内部批次证据。
