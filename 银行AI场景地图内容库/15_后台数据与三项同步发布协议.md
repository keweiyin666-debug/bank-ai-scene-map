# 后台数据与三项同步发布协议

> 2026-10-21起启用。内容新增沿用用户确认后入库原则；正式新增时同批更新流水线说明、HTML及后台。无需新建站点或数据库。

## 当前数据如何分工

| 数据 | 存放位置 | 作用 |
|---|---|---|
| 原件、完整客户映射、证据、量化性质、审批记录 | 本地L4文档、08/10/11/13号台账、批次审核包 | 业务事实与审核依据，不进入公开仓库 |
| 经审核的完整发布投影 | `data/published-catalog.json`，来源批次由08号索引补齐 | 构建输入；维护业务内容时先核对源卡，不能在此创造事实 |
| 完整运行目录与公开流水线摘要 | Supabase `public.scene_map_catalog` 中 `bank-main` 的JSON快照 | 包含全部L1/L2、可选L3、完整L4字段、来源批次引用；页面默认从此读取 |
| 单HTML同版快照 | `output/bank-ai-scene-map/index.html` | 页面模板、渲染代码及网络不可用时的内置快照，仍只交付一个HTML |
| 访客修改的七项文案 | `public.scene_map_content` | 按稳定L4编码覆盖定义、Before/After、三项价值和反馈，不替代业务证据 |
| 访客维护的四类链接 | `public.scene_map_assets` | 按L4保存显示文字、HTTP/HTTPS地址及revision，独立于目录发布 |
| 访客维护的三个展示标签 | `public.scene_map_tags` | 数字人才、王牌场景、标杆案例布尔覆盖，独立revision及私有历史 |

完整目录采用“一条发布快照含全部场景”的轻量JSON结构，首版含63张完整卡片，并非仅登记63个编码。当前不需要另建复杂关系表或后台管理界面。整个目录和公开流水线摘要在同一事务内切换，可避免读到半批新旧混合内容。私有`catalog_history`保存被替换目录；原文案和资产历史继续保留。

页面加载流程为：同版内置快照先显示 → 请求后台完整目录并校验 → 更新业务导航、数量、搜索、卡片与详情模型 → 叠加已有共享文案及链接。后台故障或版本不兼容时保留完整快照并显示提示；有打开的详情或草稿时不强行替换，提示刷新。状态行可区分“后台场景目录”和“内置快照”。

对标准`YYYY-MM-DD-v主.次.补丁`发布编号，前端拒绝比当前快照更旧的后台目录，并明确提示后台待更新；同版或新版仍按正常流程读取。这样分阶段发布时旧后台不会覆盖新版HTML新增的卡片。正式回退须同步匹配目录和HTML，不能仅把后台切回旧版。

访客继续免登录编辑现有七项文案和四类链接。整套目录的新增、删除、改名、归属及证据通过本项目审核发布流程维护；2026-10-22仅扩展三个展示标签共享编辑。

## 每次正式新增的三项产物

1. **流水线说明。** 补充14号内部说明：客户、项目类型、原件、数量单位、处理方式、增量结果、审核记录。同步JSON中的公开脱敏摘要。即使只补强既有卡片，也须更新对应批次的结果，不能虚增来源。
2. **场景库HTML。** 先更新独立卡片、索引、台账、摘要和发布投影，再构建同版HTML。模板保持主卡片、五页签、紧凑Agent信息块及响应式布局；普通内容新增不改UI。
3. **后台数据。** 将同一发布JSON更新到原Supabase完整目录，并用`ON CONFLICT DO NOTHING`登记新增卡片的共享文案和资产行。禁止清空链接、覆盖访客修改、重置revision或以新ID替代旧卡。

三项共用`releaseId`、场景ID集合与目录SHA-256。HTML和后台是同一发布投影的两个落点，不能靠人工各维护一份。客户材料与业务事实仍以本地源卡和证据为准；前台共享改写在下次正式维护前逐项核对回收，有依据才回填源卡，不自动变成上线或收益证据。

## 固定操作

从项目根目录执行（shell按本项目约定加`rtk proxy`）：

```text
node scripts/scene-library/build-release.mjs
node scripts/scene-library/test-catalog.mjs
node scripts/scene-library/test-shared-content.mjs
node scripts/scene-library/test-shared-tags.mjs
node scripts/scene-library/check-live.mjs --snapshot
```

新增来源批次时同步维护`data/source-batches.json`中的批次ID与来源编码前缀，再在08号索引登记逐卡来源。前缀必须唯一命中，未知来源或重叠映射会停止构建，避免把后续knowhow批次算作首批试点。

构建输出为`releases/<releaseId>/catalog.json`、`apply-catalog.sql`、`manifest.json`及正式HTML。构建会核对源卡存在、索引标题、来源引用、编码唯一、字段、三项价值、批次数量、流水线版本及发布批次。快照仅留本地，不能上传GitHub。

随后在已登录的原Supabase项目执行本批SQL；只对已审核投影进行发布。运行`node scripts/scene-library/check-live.mjs`，核对后台目录指纹与场景集合，并确认迁移前后共享文案、链接、revision未变。若访客在这段时间内编辑导致比较不同，应分析真实并发变化，不能恢复旧快照覆盖新编辑。

最后向原GitHub仓库发布根`index.html`及公开维护资料（规则、技能、脚本、公开源卡、目录、流水线和迁移），不提交原件、内部客户映射或共享数据快照。等待Pages完成，再检查线上HTML指纹、HTTP200、浏览器后台加载状态、搜索筛选、详情和已有编辑入口。流水线、后端及HTML之间不能做跨服务数据库事务，必须记录各阶段状态并最终核对；任何一步失败时保留进度，明确未完成项，不能宣称三项同步完成。

目录载荷使用schemaVersion控制兼容。仅添加同结构内容时，已部署的v0.6页面会在刷新后加载后台新目录；仍按用户要求重新生成和同步HTML快照。结构变更先部署兼容读取逻辑，再切换新格式，不能让旧页面读取不兼容结构。

回退须同时选定匹配的目录、HTML与流水线版本；在私有目录历史或原GitHub历史恢复。不要回退共享链接、文案或revision。每次后台执行前核对当前release，避免旧SQL覆盖较新的已发布目录。

## 完成判据

- 本批新增及合并结果有客户/材料→候选→正式ID的映射；
- 三项同一release，后台与HTML内置目录逐字段一致；
- 页面实际显示后台来源，而非仅可用的回退快照；
- 已有共享数据保留，新卡片可以正常读取编辑状态；
- 12号发布记录及99号变更记录写明已生成、已应用、已部署、已验证的实际状态。

## 2026-10-22 双组织视角发布扩展（v0.7.0已实现并完成后台核验）

部门与业务域共用原Supabase完整目录和同一组L4 ID，不另建空间或场景正文副本。新增/补强内容的审核包及流水线同时记录部门关系处理结果，来源数、唯一L4数、部门关系数分别统计；具体规则见[16号计划](16_部门与业务域双视角组织及调整计划.md)。

目录schema2承载部门字典和已确认的部门—L4关系，前端及严格校验器兼容schema1/2。已先部署兼容页面；本批SQL将数据库约束扩为1/2、保留历史目录及共享覆盖。三项发布最终核对同版部门关系集合、L4集合及整个目录指纹；全过程保留七项文案、三类标签、四类链接及revision。SQL包含目录独占锁、过期release保护及同版不同指纹拒绝，避免旧脚本覆盖新目录。

部门关系唯一源为`data/department-mapping.json`；运行`refresh-departments.mjs`生成源卡关系段、17号索引及发布关系。用户批准首批65张卡157条通用职责建议，不等于批准后续关系。v0.6.1历史产物及快照不改写，本次新release为v0.7.0；远端实际状态见12号记录。

构建同时提供`apply-with-tags.sql`，将标签增量迁移与目录发布合为一次执行，适用于当前标签表尚未启用的原项目；已经启用时脚本保持幂等。执行前仍需本地共享快照，执行后仍须`check-live.mjs`实际读回，不能将文件生成或用户点击Run等同于验证通过。


## 2026-10-22 展示标签共享编辑扩展

用户授权访客免登录编辑数字人才（`digitalTalent`）、王牌场景（`flagship`）、标杆案例（`benchmark`）三个布尔展示标签。详情顶部编辑、保存或取消；三项可同时勾选或全部取消。主卡片、详情、标签筛选及数量共用合成数据，刷新从原Supabase读取。`scene_map_tags`保存覆盖、revision与私有历史，受限RPC校验白名单并做版本冲突检查。普通目录发布只登记新增行，不清空覆盖，不重置revision。覆盖为false会取消基线标签；后台null仅表示移除覆盖、恢复基线，不能混淆。

标签调整只改变公开展示，不自动修改客户来源、数字人才身份依据、生产成熟度、已验证成效或量化性质。下轮正式维护时核对共享改动与源卡证据。L3王牌场景群与本次L4标签分别维护。页面不新增后台登录、不增加导出或测试打开功能。新增权限是三个展示字段，不允许访客新增/删除卡片或改变业务归属。三项同步新增需同时登记标签行，并验证原链接、文案和标签覆盖完整保留。
