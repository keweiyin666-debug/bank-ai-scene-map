## 1. 体系定位

本文件固化银行 AI 场景地图从内容台账到 HTML 的发布契约。业务事实仍以 L1—L4 台账为准，HTML 只负责展示，不成为新的事实来源。

```text
客户材料
→ L1 / L2 / 可选 L3 / L4 内容台账
→ 标签、成熟度和量化性质校验
→ 页面发布摘要
→ HTML 场景对象
→ 主页面 L4 卡片
→ 右侧半屏详情抽屉
```

稳定基线包括：

- 左侧部门默认导航与原L1业务域导航可切换，同一L4集合不复制；
- 内容区按 L2 价值链环节分组；
- L3 仅在确有场景群时作为介绍区，不阻挡 L4 直接归入 L2；
- 每个 L4 在主页面直接显示一张独立场景卡片；
- 点击 L4 卡片后，右侧半屏抽屉展示五段式详情；
- 桌面端使用半屏抽屉，移动端自动切换为全宽抽屉；
- 搜索、业务域筛选、王牌场景、标杆案例、数字人才和 D01—D04 筛选保持可用。

除非用户明确提出页面改版，后续内容填充不得调整组件层级、页签数量、抽屉方式、字体体系、颜色语义和响应式规则。

## 2. 页面信息架构

```text
银行 AI 场景地图
├─ 页面级能力说明：D01—D04、资产网关、AI-L1—AI-L3
├─ L1 一级业务域导航
│  └─ L2 价值链环节
│     ├─ 可选 L3 场景群介绍
│     └─ L4 具体场景卡片
│        └─ L4 右侧详情抽屉
│           ├─ 场景概览
│           ├─ Before / After
│           ├─ 能力深度
│           ├─ 业务价值
│           └─ 资产与边界
└─ 方法说明与页面口径
```

允许的内容路径只有：

```text
L1 → L2 → L4
L1 → L2 → L3 → L4
```

场景层级按业务任务组织，不按技术路线拆分。主要使用人/组织和实际业务需求共同定义 L4 身份；BI、AI、联合 Agent 是同一 L4 下的实现路径，不改变 L1—L4 归属。所有场景默认具备 BI 分析基础，首页既有 D01—D04 与 AI-L1—AI-L3 能力说明保持不变。

## 3. 主页面 L4 卡片契约

主卡片用于快速比较场景，只保留以下五组信息，顺序固定：

| 顺序 | 卡片区域 | 内容来源 | 展示要求 |
|---|---|---|---|
| 1 | 场景标题区 | 场景名称、一句话场景定义 | 使用业务语言，不展示技术产品名堆叠 |
| 2 | Before | 当前作业方式 | 写清角色、动作和主要断点，不提前写价值结论 |
| 3 | After | 新作业方式 | 写清 Dora 或联合 Agent 的产物，以及人工保留的责任 |
| 4 | 用户反馈 | 用户反馈 | 第一人称；非访谈原话统一标注“预期体验” |
| 5 | 核心价值 | 效率、质量/风险、经营/管理 | 固定三句话，每句对应一个价值维度 |

主卡片不得显示：独立量化数据板块、场景编码、场景版本、成熟度、D01—D04 状态、AI 决策参与等级、Agent 协作形态、资产网关能力编码、实现范围和场景资产。

## 4. 详情抽屉契约

详情抽屉保持五个固定页签。后续新增字段时，应优先归入现有页签，不新增页签。

| 页签 | 固定内容 | 主要字段 |
|---|---|---|
| 场景概览 | 30 秒理解场景，并显示业务域、业务环节、AI 参与度和成熟度 | 一句话场景定义、Before、三句话价值、所属 L1/L2、AI 决策参与等级、成熟度 |
| Before / After | 对照同一项业务工作在引入 AI 前后的变化 | Before、After |
| 能力深度 | 回答“是什么、为什么、凭什么、怎么做” | D01—D04 覆盖状态 |
| 业务价值 | 展示三项价值和用户体验 | 效率价值、质量/风险价值、经营/管理价值、用户反馈；不显示 V01/V02 等性质标签和独立量化数据板块 |
| 资产与边界 | 说明当前能做到什么、依赖什么、由谁确认 | 场景资产、当前实现范围、能力边界、场景编码、版本、所属路径、价值标签、资产网关状态 |

详情页的业务结论、任务流转、对外材料和正式推送均不得暗示为无人审核。AI-L3 也必须保留人工确认。

## 5. HTML 场景对象数据契约

`04_L4_具体场景.md` 是 L4 业务事实源，HTML 中的场景对象是发布投影。字段映射如下：

| 台账字段 | HTML 键 | 类型 | 说明 |
|---|---|---|---|
| L4 编码 | `id` | 字符串 | 页面内唯一 |
| 具体场景名称 | `title` | 字符串 | 主卡片标题 |
| 一句话场景定义 | `definition` | 字符串 | 主卡片摘要与详情概览 |
| AI 决策参与等级 | `decision` | 字符串 | `AI-L1`、`AI-L2` 或 `AI-L3` |
| 四问能力覆盖 | `abilities` | 对象 | `D01`—`D04` 分别使用 `done`、`partial`、`planned`、`na` |
| 成熟度 | `maturity` | 字符串 | 无证据时保留“待核实” |
| 场景版本 | `version` | 字符串 | 如 `v0.1`、`v1.0` |
| 王牌场景标签 | `flagship` | 布尔值 | 只作为展示标签 |
| 标杆案例标签 | `benchmark` | 布尔值 | 仅有真实客户应用和可追溯案例证据时为 `true` |
| 数字人才标签 | `digitalTalent` | 布尔值 | 仅来源于数据人才计划、BI/AI 大赛、人才孵化或员工自主创新，且具备可追溯团队和材料时为 `true` |
| 资产网关能力 | `gateway` | 布尔值 | 仅高度依赖历史 BI 资产时为 `true` |
| 价值标签 | `values` | 字符串数组 | 一个主标签，可带不超过两个辅助标签 |
| 主要使用角色 | `role` | 字符串 | 详情“资产与边界”补充信息 |
| 触发时点 | `trigger` | 字符串 | 详情“资产与边界”补充信息 |
| 业务任务 | `task` | 字符串 | 详情“资产与边界”补充信息 |
| 主要数据范围 | `dataScope` | 字符串 | 不包含密码、Token 或敏感样例 |
| 输出结果 | `outputs` | 字符串 | 报告、清单、摘要、图表或待办等业务产物 |
| Agent 协作形态与说明 | `collaboration` | 字符串 | 使用 C03 时写明主 Agent、Dora 子任务和返回产物 |
| 人工确认点 | `manualCheck` | 字符串 | 写清谁确认口径、结论、推送或任务流转 |
| Before | `before` | 字符串 | 主卡片与详情共用 |
| After | `after` | 字符串 | 主卡片与详情共用 |
| 用户反馈 | `feedback` | 字符串 | HTML 中保留引号，不重复添加“预期体验”前缀 |
| 三项价值 | `metrics` | 对象数组 | 固定三项：`dimension`、`nature`、`text` |
| 量化依据 | `quantBasis` | 字符串 | 仅用于内容治理与证据审查，不直接显示在 HTML |
| 当前实现范围 | `scope` | 字符串 | 明确已覆盖范围与待核实范围 |
| 能力边界 | `boundary` | 字符串 | 写清当前不做或依赖外部能力的部分 |
| 场景资产 | `assets` | 对象 | 固定维护方案 PPT、看板 Demo、Dora 体验、短视频 |

L1、L2 和可选 L3 信息由 `domains[].sections[]` 继承，不在每个 L4 对象中重复维护。页面状态不写入 HTML 对象；只有台账状态为“发布”，或用户明确允许进入原型的候选场景，才能加入页面数据。

### 5.2 资产超链接编辑（v1.4，共享存储）

- 在既有“资产与边界”页签内提供“编辑链接”，保留四类资产卡片和原资产状态；主卡片及五页签结构保持不变。
- 每类链接只编辑显示文字和 HTTP/HTTPS 地址，默认文字分别为“查看方案”“打开看板”“进入体验”“观看视频”；已配置链接以浅蓝圆角按钮展示，并在新标签页打开。未配置地址显示“未配置链接”，不改写资产成熟度或业务事实。
- 单 HTML 通过 Supabase Data API 按稳定 L4 编码读取 `scene_map_assets`，通过 `scene_map_save_links` RPC 保存；不再使用 localStorage，不自动迁移旧浏览器数据。其他访问者刷新页面或重新打开详情后读取最新值。
- 访客免登录；本链接接口只能修改四类资产的 `label` 和 `url`，文案另走第 5.3 节接口；不能修改场景身份、标题、数据库结构或 GitHub 源码。服务端校验四种资产键、字段、长度和 HTTP/HTTPS 地址。前端只配置公开 publishable key，不包含数据库密码或高权限密钥。
- 支持取消修改与确认后移除链接；输入内容按纯文本转义，拒绝非 HTTP/HTTPS 地址；保存成功必须以云端响应为准，网络或服务失败时保留输入并提示失败，不降级为本地假保存。
- 编辑使用 revision 乐观并发控制；遇到冲突保留输入并提示重新加载，不静默覆盖其他访客的修改。服务端保留每场景最近 50 次修改前的历史值，供项目所有者在控制台人工恢复，不向访客开放历史表。
- 用户明确选择公开免登录编辑，因此任何互联网访客都能修改链接，不保证只由同事维护，也不保证免受恶意改写或额度消耗；不要在链接中填写口令、私密签名或客户敏感信息。
- 按用户要求，不设置“测试打开”、HTML 导出按钮或浏览器存储说明文案。
- 发布验收补充：四类链接保存/跨页面刷新同步、取消、移除、并发冲突、网络失败提示、移动端布局及原搜索/筛选均需验证；已完成项以发布记录为准，不把实现代码等同于已验证。

### 5.3 共享文案编辑与页面联动（v1.5）

本次为用户明确授权的交互扩展，保留主卡片五组信息、详情五页签、半屏抽屉、导航和颜色语义。

| 编辑入口 | 唯一共享字段 | 联动位置 |
|---|---|---|
| 30 秒场景概览 → 编辑概览 | `definition`、`before`、`efficiency`、`quality`、`management` | 标题摘要、主卡片、概览、Before 对照、业务价值；搜索使用更新后的定义 |
| 同一件事，现在怎么做 → 编辑对照 | `before`、`after` | 主卡片、概览中的问题、Before/After 对照 |
| 业务价值与用户体验 → 编辑价值与反馈 | `efficiency`、`quality`、`management`、`feedback` | 主卡片、概览中的价值、三项价值和用户反馈 |

- 独立 `scene_map_content` 表保存覆盖字段；`scene_map_save_content` RPC 仅接受上述七个字段。每项为 1—2000 字纯文本，客户端转义显示；不开放场景改名、标签、能力、证据、成熟度或量化性质修改。
- 表和 RPC 与资产链接分开，按相同 L4 编码关联；匿名仅能 SELECT，通过受限 RPC 保存。原 `scene_map_assets`、已有链接和 revision 不被文案保存触碰。增量 SQL 位于 `migrations/20261021_shared_content.sql`，不得把初始化脚本当作清库脚本运行。
- 每次只提交实际改变的字段；revision 冲突保留草稿，取消后重新读取云端版本，再编辑。保存以云端成功响应为准，服务失败保留填写，不假装本地保存。关闭含草稿的详情需确认放弃，保存中不能关闭。每场景保留最近 50 次修改前版本，历史表不向访客开放。
- 一个场景未登记只停用该场景编辑，不导致其余场景共享服务失败。新增场景入库后须增量登记资产行及内容行；`ON CONFLICT DO NOTHING` 保护已有链接和文案。
- 同页保存后立即更新外部卡片、详情标题及相关面板；其他访客刷新或重新打开详情取得更新。无需导出 HTML，无需访客登录；不承诺实时推送。
- 云端文案是发布覆盖层，源 Markdown 仍记录业务事实与证据。后续材料提炼或重新生成 HTML 前须读取并比对覆盖层；经核验后回填独立场景文档及摘要。重新发布不得自动清空覆盖值；只有明确完成回收或用户授权恢复基线时，才按最新 revision 以 `null` 移除相应覆盖。
- 修改价值措辞不会自动提升 V00—V04 性质，也不证明收益或上线状态；缺数字仍保持待确认，预期体验仍标注预期体验。

### 5.4 四问能力区尺寸基线

仅压缩详情中的 `#detail-ability`：四张能力卡固定两列，间距 10px，内边距 12px 14px，标题 15px、说明 12px；手机端内边距 11px、标题 14px。保留 D01—D04、问题说明和覆盖状态。首页能力框架和其他卡片样式不作本次调整。后续普通内容更新不得覆盖这些局部规则。

### 5.5 Agent 场景上下文小块（v1.5.1）

- 用户指定“资产与边界”底部补充信息主要供Agent快速读取，改为低视觉权重的紧凑信息块；不改变上方资产卡、实现范围和责任边界。
- 固定使用 `aside.agent-context` + `dl/dt/dd` 语义结构，根节点保留 `data-scene-id`，12个字段保留稳定 `data-field`：`role`、`trigger`、`task`、`dataScope`、`outputs`、`collaboration`、`manualCheck`、`id`、`version`、`path`、`values`、`gateway`。
- 桌面双列、Agent协作跨两列；小于560px单列。字号11px、行高1.5、字段内边距5px 0（手机4px 0）、块内边距10px 12px，取消逐行分隔线和粗体，保留浅底细边框。
- 全部内容常驻DOM并完整显示，不折叠、不截断、不省略长文，不为了缩小块而删除责任/协作字段。所有值按纯文本转义；共享文案、业务数据和后台接口不改变。
- 普通场景填充仅更换字段值，不恢复原大行距表格或扩大字号。

### 5.6 完整后台目录与同版快照（v0.6起）

页面优先读取原Supabase的`scene_map_catalog`完整发布目录，内容包括L1/L2/可选L3、全部L4业务字段和公开流水线摘要；内置同版JSON只作首屏及网络失败回退。七项文案与四类链接继续独立叠加，不因重发目录丢失。详见15号协议。

内容发布输入为`data/published-catalog.json`及08号来源索引，统一由`scripts/scene-library/build-release.mjs`生成HTML、后台JSON/SQL和指纹清单。普通内容修改不在生成HTML手改数据。页面模板为`scripts/scene-library/page-template.html`，核心UI仍遵循v1.5.1；新增的流水线说明使用页面底部折叠区，内部客户名单和原件路径不公开。

后台目录校验失败时整批拒绝，不能部分替换；数据状态行明确区分后台与内置快照。已打开详情或存在草稿时不强行替换目录。三项发布必须核对相同releaseId、场景ID集合和目录指纹。

### 5.7 部门与业务域双视角契约（v0.7.0已实现）

本节是对原“仅L1导航”限制的已确认扩展；其他基线不变。完整规则及历史工作量见[16号计划](16_部门与业务域双视角组织及调整计划.md)。

- 导航入口为“按部门｜按业务域”，部门在前，无显式访问上下文时默认部门，以全部场景起始；部门不是新L1。

- 目录及严格校验器已支持schema1/2；schema2增加部门字典与逐卡关系，旧目录仍可兼容读取。SQL已生成，数据库约束与后台目录是否实际应用以12号读回记录为准。

## 6. 内容长度与写作口径

| 字段 | 建议长度 | 写作重点 |
|---|---:|---|
| 场景名称 | 6—18 个汉字 | 使用业务任务命名 |
| 一句话场景定义 | 40—80 个汉字 | 角色、时点、任务、产物 |
| Before | 45—100 个汉字 | 当前动作、工具、耗时或断点 |
| After | 55—120 个汉字 | AI 动作、输出、人工责任 |
| 用户反馈 | 25—65 个汉字 | 第一人称、具体体验，不写宣传口号 |
| 单条价值 | 20—80 个汉字 | 维度、指标性质、基线/目标/周期/范围 |
| 当前实现范围 | 40—120 个汉字 | 已覆盖与未覆盖边界 |

长度是页面可读性建议，不得为了满足字数删掉责任边界或编造量化信息。

## 7. 缺失信息降级规则

- 缺少可靠数字：使用 `V00 待确认`，写明缺少基线、目标值、统计周期还是适用范围；
- 缺少试点或上线证据：成熟度写“待核实”，不得直接标为 M3/M4；
- 缺少用户原话：写“预期体验”，不得伪装成客户证言；
- 缺少场景资产：使用“暂无”“待提炼”“待核实”或“待上线”；
- 缺少 Before、After、用户反馈或任一价值维度：保留为候选，不进入正式发布；
- 不需要 L3：L4 直接挂在 L2 下，不创建空壳场景群；
- 一般数据分析：不得默认设置资产网关标签。

## 9. 发布流程

1. 将材料中的事实、客户观点、顾问判断和待验证项分开记录；
2. 判断 L1、L2、可选 L3 和 L4，并与现有场景去重；
3. 在 `04_L4_具体场景.md` 完成单场景字段；
4. 使用 `05_标签与能力字典.md` 校验 D01—D04、AI-L1—AI-L3、V00—V04、协作和网关标签；
5. 仅将页面状态为“发布”或用户明确允许进入原型的场景写入 `06_页面发布摘要.md`；
6. 将已校验字段映射为 HTML 场景对象，不直接在 HTML 中创造新的业务事实；
7. 更新由台账计算的页面数量；
8. 验证主卡片、五段式详情、搜索、筛选、关闭抽屉、桌面端和移动端；
9. 在 `99_变更记录.md` 记录内容和页面更新。
