## 1. 管理口径

- L4 是页面直接展示的独立场景卡片；合法路径为 `L1 → L2 → L4` 或 `L1 → L2 → L3 → L4`。
- 每个发布场景必须有一份独立文档，完整维护角色、触发、任务、Before、After、预期体验、三项价值、D01—D04、AI 参与等级、协作、边界与来源。
- 本文件只维护场景主索引和归属关系；完整字段见 `07_场景卡片HTML发布体系.md`，快速索引见 `08_L4场景卡片索引.md`。
- HTML 主卡片展示场景定义、Before、After、用户反馈和三项核心价值，不单独展示“量化数据”板块。
- HTML 详情保留业务价值正文，但不展示 V01/V02 等指标性质标签，也不单独展示量化数据或量化依据板块。
- 页面场景标签仅使用“王牌场景、标杆案例、数字人才”；资产网关保留为详情中的横向能力，不作为场景筛选标签。
- L4 按主要使用人/组织和实际业务需求识别与去重。BI、AI、联合 Agent 是同一场景下的实现路径；客户、产品、渠道、报表和工具差异不单独生成 L4。
- 量化指标和 V00—V04 性质继续在独立文档中维护，用于内部治理与证据校验，不因页面简化而删除源数据。
- 2026-10-22起新增/补审候选同时分析部门主责与协同，按L4建立关系；业务域与部门是同一集合的组织视角，不据此新增编码。既有65张卡的157条通用职责建议已获用户确认；关系唯一台账为`data/department-mapping.json`，独立源卡关系段及17号索引由脚本生成。部门字典、依据和审核口径见[16号计划](16_部门与业务域双视角组织及调整计划.md)，以后新增关系仍须审核。
