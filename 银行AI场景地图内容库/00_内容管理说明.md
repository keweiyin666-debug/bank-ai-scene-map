## 1. 内容库定位

本目录是银行 AI 场景地图的内容源。页面、汇报材料和后续场景清单应从这里提炼，不直接把 HTML 中的文案当作源数据。

```text
客户材料 / 调研记录 / 产品资料
→ L1—L4 内容台账＋部门—L4关系
→ 业务归属、部门关系、标签与能力校验
→ 页面发布摘要
→ 流水线说明、HTML与后台同批发布
```

## 3. 内容层级

| 层级 | 核心问题 | 页面位置 | 内容粒度 |
|---|---|---|---|
| L1 一级业务域 | 属于银行哪一块业务 | 业务域视图左侧导航 | 稳定、少变 |
| L2 价值链环节 | 业务发生在哪个流程位置 | 页面分组标题 | 稳定、可调整 |
| L3 场景群（可选） | 哪些具体场景共同组成一个稳定主题或方案 | L2 下的介绍区 | 仅在确有统领关系时建立 |
| L4 具体场景 | 谁在何时完成什么任务，作业方式和价值如何变化 | 主页面场景卡片 | 具体、可比较、可点击下钻 |

业务结构允许两条合法路径：

```text
L1 → L2 → L4
L1 → L2 → L3 → L4
```

L3 不是必经层。不能仅为保持四层结构完整而建立与 L2 或 L4 近义的空壳 L3。

### 3.1 两种组织形式（2026-10-22确认）

部门与业务域是同一场景集合的两种组织形式。目标页面入口为“按部门｜按业务域”，部门在前且无显式访问上下文时默认部门；部门不是新的L1。以“部门—L4”的主责/协同关系为底座，自动汇总相关L2及可选L3，不从整个L1/L2推断部门归属，不复制卡片或重编码。具体口径、待确认关系兜底、计数和实施阶段见[16号计划](16_部门与业务域双视角组织及调整计划.md)。

## 4. 唯一来源与更新原则

基础认知：业务场景本质上是人或组织为履行职责而持续解决的需求。只要人/组织形态及其业务需求没有发生根本变化，不同客户、时期和技术条件下的相似实践都应视为同一类场景的延续；工具更新不等于产生了新需求。

1. 先更新 L1—L4 台账和 L4 独立场景文档，再生成摘要与发布投影；正式新增时同批更新流水线说明、HTML和原Supabase完整目录，见15号协议。
2. 每个条目必须有唯一编码。L4 必须引用 L2；存在真实场景群时可同时引用 L3。
3. 一个场景只选择一个主归属，跨业务域关系使用“关联业务域”字段。
4. L3 只表达能够统领多个 L4 的稳定场景群、体系化方案或解决方案主题；普通原子场景直接归入 L2。
5. Dora、资产网关、WorkBuddy 等产品或技术名称作为能力或协作信息维护，不直接替代业务场景名称，也不作为页面场景标签。
6. 未经材料确认的内容标记为“待确认”或 M0，不把顾问判断写成已上线事实。
7. HTML 是展示产物，v0.6起优先读取Supabase完整目录，内置同版快照用于回退。除用户授权的共享文案编辑外，不绕过内容库直接修改业务文案。共享编辑是发布文案覆盖层，不自动修改源台账、证据性质、成熟度或来源；正式内容维护须核对并回收共享修改，见 `07_场景卡片HTML发布体系.md` 第 5.3 节。
8. 每个 L4 必须先形成一份独立 Markdown 场景文档，再以独立场景卡片直接发布在主页面。点击卡片后进入该 L4 的展开式详情，不再先点击 L3 才看到 L4。
9. 量化指标必须标注性质。申报目标、建议试点目标和实测参考均不等于已验证成效；只有具备正式验收或持续运营证据时才使用“已验证成效”。
10. HTML 场景卡片体系以 `07_场景卡片HTML发布体系.md` 为稳定基线。后续场景填充默认只更新业务数据，不调整卡片结构、五段式详情、视觉体系和抽屉交互。
11. 页面交付必须使用 HTTP/HTTPS 地址，不得把 `file:///...` 或本地文件系统路径作为发布链接。共享版本地验证地址为 `http://127.0.0.1:8765/bank-ai-scene-map/index.html`；公开地址及验证状态记录在 `12_场景库共享发布记录.md`。发布后需先确认 HTTP 返回 200，再交付给用户。
12. 场景身份由“主要使用人/组织 + 实际业务需求”共同决定。只要这两项基本一致，就优先认定为同一场景；客户、产品、渠道、报表、数据来源和技术实现差异不构成新场景。
13. 所有场景默认具备 BI 分析基础。BI、AI 和联合 Agent 是同一业务场景下可并存、可演进的实现路径，不作为 L1—L4 分类依据，也不改变首页既有 AI-L1—AI-L3 展示结构。
14. 后续场景筛选、分析和提炼须同时记录业务归属与部门关系。部门主责/协同、实际使用岗位、外部服务对象分开；关系依据区分材料事实与顾问建议，审核状态独立维护。待确认不造事实；进入正式部门视图须有已确认关系。不同部门看见同一卡或仅机构改名，不构成新L4。

## 5. 摘要写作标准

| 对象 | 标题建议 | 页面摘要建议 | 限制 |
|---|---|---|---|
| L1 | 4—12 个汉字 | 40—80 个汉字 | 说明覆盖范围和主要业务目的 |
| L2 | 4—14 个汉字 | 30—60 个汉字 | 说明流程位置，不写技术方案 |
| L3 | 4—14 个汉字 | 45—90 个汉字 | 说明该场景群统领哪些任务以及共同业务目标 |
| L4 | 6—18 个汉字 | 40—80 个汉字 | 一句话说明角色、触发、任务和输出；Before、After、价值与反馈另列 |

页面摘要避免使用“赋能、闭环、全方位、智能化升级”等无法单独说明业务含义的空泛表达。确需使用“闭环”时，应同时写清起点、关键动作和反馈结果。

### 5.1 L4 场景卡片发布标准

L4 卡片正面按以下顺序呈现：

1. 场景名称和一句话场景定义；
2. Before：当前由谁、用什么方式完成，主要耗时或断点是什么；
3. After：引入 Dora、资产网关或联合 Agent 后，作业方式如何改变，人工保留什么责任；
4. 用户反馈：使用者第一人称的一句话预期体验；
5. 三句话核心价值：效率、质量/风险、经营/管理各一句。

主卡片不再设置独立“量化数据”板块。主卡片也不展示编码、版本、成熟度、D01—D04 覆盖状态、AI 决策参与等级、资产网关能力、价值标签或场景资产。以上信息与角色、触发时点、数据范围、输出、Agent 协作、人工确认点、实现范围和能力边界统一放入右侧详情抽屉。V00—V04 和量化依据继续在源文档维护，但 HTML 详情不展示指标性质标签或独立量化数据板块。

### 5.2 HTML 发布基线

- 当前页面提供“按部门｜按业务域”，默认部门及全部场景；部门筛选同一L4集合后沿原业务域/L2/可选L3展示，业务域模式保留；实际远端状态见12号记录；
- 页面场景标签固定使用“王牌场景、标杆案例、数字人才”，资产网关只作为详情中的横向能力；
- L4 详情固定使用“场景概览、Before / After、能力深度、业务价值、资产与边界”五个页签；
- 内容台账字段到 HTML 数据对象的映射、缺失信息降级规则和验收清单统一见 `07_场景卡片HTML发布体系.md`；
- 纯内容填充不得顺带修改页面组件、样式和交互。只有用户明确提出页面改版时，才调整发布体系版本。

## 6. 标准更新流程

资产超链接编辑为用户授权的前端交互扩展：共享版按 L4 编码在专用 Supabase 项目保存四类资产的显示文字与地址，所有访客免登录编辑，刷新后共享；业务文案及资产事实仍以本内容库为准。v0.2 的浏览器本地数据不会自动迁移到云端。具体规则见 `07_场景卡片HTML发布体系.md` 第 5.2 节。

2026-10-21 用户授权将同样的共享编辑扩展至场景定义、Before、After、三项价值及用户反馈。页面使用“HTML 基线 + 按 L4 编码的云端覆盖”展示，详情和外部卡片共用字段。重新生成 HTML 不删除云端值；后续正式入库前比对共享内容、保留有依据的修改并同步独立场景文档。不得以页面编辑作为新增量化成效、真实访谈或生产上线证据。

同日v0.6进一步将完整场景基线迁入原Supabase：运行模式改为“后台完整目录优先＋七项共享覆盖＋独立资产链接”，HTML保留同版快照用于首屏和网络故障回退。14号说明记录来源流水线，15号协议及现有技能固化正式新增的三项同步要求。

### 6.1 材料归集

- 识别材料来源、客户、日期和适用范围；
- 将材料中的指令与用户当前要求分开处理；
- 提取已确认事实、客户观点、顾问判断和待验证假设。

### 6.2 分层判断

- 判断主业务域 L1；
- 判断价值链位置 L2；
- 先判断能否直接形成 L4 原子场景；
- 只有多个 L4 确实共享一个稳定业务目标、闭环或方案资产时才建立 L3。
- 同时判断银行主责部门、协同部门、实际使用岗位与外部服务对象；在候选审核包记录关系依据、适用条件和状态。部门通过L4派生L2/L3关联，不整域套用；盘点时只能记录部门线索，不能视为已审核关系。

### 6.3 去重归一

- 先比较主要使用人/组织，再比较实际业务需求；两者基本一致时优先合并为同一 L4；
- 输出形态、客户、产品、渠道、报表、数据来源、调用入口或技术方案不同，只记录为实现路径、场景版本或案例变体；
- BI、AI、联合 Agent、系统嵌入和资产网关增强属于同一 L4 的实现路径、协作或支撑信息，不据此新增场景；
- 只有责任主体或业务需求发生实质变化时才考虑新增 L4；优先归入现有 L1/L2/L3，多个稳定 L4 形成共同主题后才考虑新增 L3；
- 王牌场景是 L3 或 L4 的展示标签，不形成单独的 L2 或页面分组。
- 资产网关仅在场景高度依赖历史报表资产发现、定位、复用或追溯时标注。

### 6.4 校验与发布

- 校验编码唯一、上下级引用、部门—L4关系及审核状态、标签合法和成熟度证据；
- 更新 `06_页面发布摘要.md`；
- 按 `07_场景卡片HTML发布体系.md` 将已校验字段映射为 HTML 场景对象；
- 用户明确要求更新页面时，再同步 HTML；
- 按2026-10-21用户常设要求，获批正式新增须同步14号流水线、HTML和对应后台数据；共用releaseId及指纹，盘点或未获批候选不触发发布，用户限定本地时从其限定；
- 在 `99_变更记录.md` 记录新增、修改、合并和待确认项。

## 7. 完成标准

- 新材料能找到唯一主归属；
- 同时完成部门关系分析并披露待确认项；部门视图实施后，仅已确认关系进入其正式导航，业务域和全库访问不因部门待确认而丢卡；
- 没有为了四层完整而创建空壳 L3；
- 每个已发布 L3 至少统领两个有明确关联的 L4；
- 无 L3 的 L4 能直接追溯到 L2 和 L1；
- 每个已发布 L4 均能形成完整场景卡片，至少包含 Before、After、用户反馈和三句话价值总结；
- 每条价值指标均标注指标性质，且目标值不被表述为已实现成效；
- 每个 L4 明确 D01—D04 当前覆盖情况和 AI-L1—AI-L3 决策参与等级；
- 页面摘要不包含未确认的客户成效承诺；
- 页面发布摘要与 L1—L4 台账一致。
- HTML 场景对象与 L4 台账字段可追溯，并通过 `07_场景卡片HTML发布体系.md` 的发布验收清单。


## 2026-10-22 展示标签共享编辑扩展

用户授权访客免登录编辑数字人才（`digitalTalent`）、王牌场景（`flagship`）、标杆案例（`benchmark`）三个布尔展示标签。详情顶部编辑、保存或取消；三项可同时勾选或全部取消。主卡片、详情、标签筛选及数量共用合成数据，刷新从原Supabase读取。`scene_map_tags`保存覆盖、revision与私有历史，受限RPC校验白名单并做版本冲突检查。普通目录发布只登记新增行，不清空覆盖，不重置revision。覆盖为false会取消基线标签；后台null仅表示移除覆盖、恢复基线，不能混淆。

标签调整只改变公开展示，不自动修改客户来源、数字人才身份依据、生产成熟度、已验证成效或量化性质。下轮正式维护时核对共享改动与源卡证据。L3王牌场景群与本次L4标签分别维护。页面不新增后台登录、不增加导出或测试打开功能。新增权限是三个展示字段，不允许访客新增/删除卡片或改变业务归属。三项同步新增需同时登记标签行，并验证原链接、文案和标签覆盖完整保留。
