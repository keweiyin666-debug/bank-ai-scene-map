# L3 场景群台账（可选层）

> 维护对象：确实能够统领多个 L4 原子场景的稳定场景群、体系化方案或解决方案主题。  
> 编码格式：`BA01-01`。  
> 关键原则：L3 不是必经层；普通 L4 可以直接归入 L2。

## 1. 何时建立 L3

同时满足以下条件时才建立 L3：

- 至少有两个业务责任、触发时点或产物不同的 L4；
- 这些 L4 共享一个清晰、稳定且可复用的业务目标或闭环；
- 对外介绍时需要先解释整体方案，再展示其中的原子场景；
- L3 名称与所属 L2、下属 L4 均不构成近义重复。

以下情况直接使用 `L1 → L2 → L4`：

- L2 下只有一个或若干彼此独立的原子场景；
- 所谓 L3 只是把 L2 换一种说法；
- 所谓 L3 与某个 L4 名称、角色和任务基本相同；
- 仅为了保持四层结构完整；
- 仅因渠道、客户、报表、Agent 入口或技术实现不同。

## 2. 字段标准

| 字段 | 必填 | 填写规则 |
|---|---|---|
| L3 编码 | 是 | `L1 编码-两位序号`，发布后保持稳定 |
| 所属 L2 | 是 | 必须引用启用的 L2 编码 |
| 场景群名称 | 是 | 使用业务主题、完整方案或闭环命名 |
| 一句话定义 | 是 | 说明共同业务目标以及统领哪些任务 |
| 主使用角色 | 是 | 写主要责任者或方案购买方 |
| 经营闭环 | 否 | 有明确闭环时写关键步骤，不为展示完整而编造 |
| 王牌标签 | 是 | 是或否；仅影响展示，不改变层级 |
| 成熟度 | 是 | M0—M4，反映场景群整体项目阶段 |
| 页面状态 | 是 | 候选、发布、隐藏 |
| 页面摘要 | 是 | 45—90 个汉字，用于 L4 卡片上方介绍区 |
| 下属 L4 | 是 | 至少两个已登记 L4 编码 |
| 来源说明 | 否 | 记录方案、访谈或项目资料 |

D01—D04 和 AI 决策参与等级主要在 L4 维护；L3 只在需要时汇总下属场景的总体覆盖情况。

## 3. 当前 L3 基线

| L3 编码 | 所属 L2 | 场景群 | 页面摘要 | 下属 L4 | 王牌 | 成熟度 | 页面状态 |
|---|---|---|---|---|---|---|---|
| BA01-01 | BA01-P02 | 作战指挥中心 | 面向管理层、计财、业务条线和分支机构，将经营分析、客群作战与总支协同串成从发现问题到执行反馈的经营闭环。 | BA01-01-01、BA01-01-02、BA01-01-03 | 是 | M3/M4 待核实 | 发布 |

原文件中与 L2 或具体任务近义的候选项不再作为强制 L3。经内容审查后，应迁移为直接归属 L2 的 L4，或作为横向能力说明。
