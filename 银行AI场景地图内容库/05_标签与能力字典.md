# 标签与能力字典

> 本文件统一 L3、L4 和页面使用的标签。新增标签前先检查是否能由现有标签表达。

## 1. 场景四问能力

| 编码 | 名称 | 使用条件 | 典型输出 |
|---|---|---|---|
| D01 | 智能问数 | 回答“是什么”：数据是多少、在哪里、结构和趋势怎么样 | 指标结果、明细定位、趋势与对比 |
| D02 | 归因分析 | 回答“为什么”：从事实发现问题，定位波动并分析可能根因 | 异常定位、影响因素、归因结论 |
| D03 | 可信可控 | 回答“凭什么”：说明数据来源、指标口径、资产位置和调用链路，并保留权限与人工确认 | 来源说明、指标口径、报表定位、血缘与审计信息 |
| D04 | 业务闭环 | 回答“怎么做”：将分析结果转为名单、报告、任务、推送、督办、回录和复盘 | 行动清单、任务流转、反馈跟踪、周期复盘 |

规则：D01—D04 是业务问题深度，不再使用“主能力/辅助能力”强行二选一。每个 L4 分别标明已覆盖、部分覆盖、规划中或不适用；更深一档不代表前一档自动完整。

## 2. 资产网关能力

| 编码 | 名称 | 使用条件 |
|---|---|---|
| G01 | BI 资产发现与路由 | 需要寻找已有报表、看板、数据集或分析入口 |
| G02 | 报表与指标定位 | 需要确认指标所在报表、数据集、单元格或目录位置 |
| G03 | 资产上下文读取 | 需要理解资产摘要、参数、组件、数据集和来源关系 |
| G04 | FineReport 受控查数 | 对已注册且位置唯一的 CPT，在参数和身份确认后执行单指标或简单二维查询 |

规则：资产网关是横向支撑层，不新建业务域，也不作为页面场景筛选标签。仅当场景高度依赖历史报表、看板、数据集等既有 BI 资产的发现、定位、复用或追溯时，才在详情中显示资产网关能力。一般数据分析场景不得默认贴标。除 G04 外，资产网关返回资产事实和定位信息，不代表实时业务数值。

## 3. Agent 协作形态

| 编码 | 名称 | 定义 |
|---|---|---|
| C01 | Dora 独立 Agent | 用户直接进入 Dora 使用业务 Agent |
| C02 | 业务系统嵌入调用 | 企业门户或业务系统通过接口调用 Dora |
| C03 | 联合 Agent | WorkBuddy、OpenClaw 或其他主 Agent 将数据分析子任务交给 Dora |
| C04 | Dora 外接能力 | Dora 通过 MCP 调用资产网关或其他外部数据与工具 |

规则：协作形态只在 L4 记录。使用 C03 时必须写明主 Agent、Dora 子任务、返回产物、权限传递和人工确认点。

### 3.1 实现路径与场景身份

- 所有业务场景默认可以由 BI 指标、模型和看板承载；无需在首页另建 BI 分类。
- 同一 L4 可以同时存在 BI、AI 和联合 Agent 三类实现路径，并随客户条件和建设阶段逐步演进。
- BI、AI、联合 Agent 只描述“怎么实现”，不回答“是不是同一个场景”。场景身份只由主要使用人/组织和实际业务需求决定。
- 客户、产品、渠道、报表、数据源、调用入口或工具不同，原则上作为实现路径、场景版本或案例变体记录。

## 4. AI 决策参与等级

| 编码 | 名称 | 定义 |
|---|---|---|
| AI-L1 | 信息支持 | AI 提供事实、查询结果、图表和报告，不替业务人员作判断 |
| AI-L2 | 分析建议 | AI 提供归因、风险提示或行动建议，由业务人员判断和决策 |
| AI-L3 | 人工确认后闭环 | AI 形成名单、任务、推送或流转草稿，经人工确认后执行并跟踪反馈 |

规则：使用 `AI-L1—AI-L3`，避免与地图层级混淆。当前不设置无人审核的高度自动决策；正式报告、对外推送、营销触达、授信、风控处置和任务流转均保留人工确认。

## 5. 场景成熟度

| 编码 | 名称 | 判断口径 |
|---|---|---|
| M0 | 场景设想 | 已发现方向，尚未验证具体需求 |
| M1 | 需求确认 | 已明确用户、任务和业务价值 |
| M2 | 方案验证 | 正在开展原型或 POC 验证 |
| M3 | 业务试点 | 已在真实部门或用户中试用 |
| M4 | 已上线 | 已进入正式运行或持续运营 |

规则：展示材料、界面截图或领导评价不能单独替代项目台账。无法确认试点和上线范围时写“待核实”。

## 6. 价值标签

| 标签 | 使用范围 |
|---|---|
| 经营增长 | 获客、客户经营、价值提升、收入或业务机会 |
| 管理决策 | 经营洞察、问题诊断、资源配置、策略研讨 |
| 运营提效 | 减少取数和材料整理、提升流程或作业效率 |
| 风险合规 | 风险识别、监测、检查、整改和合规支持 |
| 客户与员工体验 | 改善客户服务或降低员工使用和作业负担 |

规则：每个 L4 选择一个主价值标签，可增加不超过两个辅助标签。L3 可汇总下属 L4 的共同价值标签。不要为视觉对称新增近义标签。

## 7. 页面状态

| 状态 | 含义 |
|---|---|
| 候选 | 已进入内容库，但暂不作为正式页面内容承诺 |
| 发布 | 可以进入页面主视图或下钻详情 |
| 隐藏 | 保留历史记录，当前页面不展示 |

## 8. 价值指标性质

| 编码 | 页面标签 | 使用条件 | 推荐措辞 |
|---|---|---|---|
| V01 | 申报目标 | 来源材料中明确写明申报、立项或建设目标 | “申报目标：预计……” |
| V02 | 建议试点目标 | 为试点验收建议设置，尚未获得业务方正式确认 | “建议试点目标：……” |
| V03 | 实测参考 | 已有测试、演示或局部运行记录，但不代表全面上线成效 | “实测参考：在……条件下……” |
| V04 | 已验证成效 | 有验收报告、正式运营数据或可追溯客户证据 | “已验证成效：在……范围和周期内……” |
| V00 | 待确认量化目标 | 当前缺少可靠基线、目标值或统计周期 | “待确认量化目标：需补充……” |

规则：

- 每句价值先写维度，再写指标性质，例如“效率｜V02 建议试点目标”。
- 每个 L4 固定保留效率、质量/风险、经营/管理三个维度；暂不适用时说明原因，不编造对称数字。
- V01、V02、V03 不得在标题、摘要或用户反馈中改写为“已提升”“已达到”。
- V04 必须记录证据来源、适用范围和统计周期；没有这些信息时降级为 V03 或 V00。

## 9. 页面场景标签

| 标签 | 使用条件 | 当前口径 |
|---|---|---|
| 王牌场景 | 已形成完整闭环、代表性强且材料充分，可作为核心解决方案对外介绍 | 当前用于作战指挥中心下属三个场景 |
| 标杆案例 | 已有真实客户应用、明确适用范围和可追溯案例证据 | 无客户证据时不得标记 |
| 数字人才 | 来源于数据人才计划、BI/AI 大赛、人才孵化或员工自主创新，并具备可识别的作者/团队、来源材料和可用场景证据 | 表示场景来源与人才孵化属性，不代表 AI 成熟度或客户标杆 |

规则：

- 页面场景标签与价值标签、成熟度、资产网关能力相互独立。
- 同一场景可同时具备多个页面标签，但每个标签都必须有对应证据。
- 2026-10-22本地内容库及HTML共65个场景（本轮CBS新增2个）；线上状态以12号发布记录为准。基线29个数字人才标签、3个王牌标签不变，访客展示覆盖另行叠加。knowhow准标杆来源不自动转为页面标杆或数字人才，“标杆案例”仍需逐场景认定。


## 2026-10-22 展示标签共享编辑扩展

用户授权访客免登录编辑数字人才（`digitalTalent`）、王牌场景（`flagship`）、标杆案例（`benchmark`）三个布尔展示标签。详情顶部编辑、保存或取消；三项可同时勾选或全部取消。主卡片、详情、标签筛选及数量共用合成数据，刷新从原Supabase读取。`scene_map_tags`保存覆盖、revision与私有历史，受限RPC校验白名单并做版本冲突检查。普通目录发布只登记新增行，不清空覆盖，不重置revision。覆盖为false会取消基线标签；后台null仅表示移除覆盖、恢复基线，不能混淆。

标签调整只改变公开展示，不自动修改客户来源、数字人才身份依据、生产成熟度、已验证成效或量化性质。下轮正式维护时核对共享改动与源卡证据。L3王牌场景群与本次L4标签分别维护。页面不新增后台登录、不增加导出或测试打开功能。新增权限是三个展示字段，不允许访客新增/删除卡片或改变业务归属。三项同步新增需同时登记标签行，并验证原链接、文案和标签覆盖完整保留。
