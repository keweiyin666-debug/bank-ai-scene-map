| L3 | 无 |
| 主要使用角色 | 分行计划财务部、支行/网点现金需求申报人员 |
| 触发时点 | 每日次日现金计划编制和申请变化 |
| 业务任务 | 掌握次日现金需求并合理调配库存 |
| 定义 | 分行计财人员汇总支行网点的次日现金使用申请，核查需求与库存后形成经授权确认的调配安排。 |
| Before | 分行计财每天需要掌握各支行头寸使用情况，汇总和库存调配依赖对各网点需求的及时收集。 |
| After | 案例材料由支行和网点发起申请，分行计财查询次日汇总并据此调配现金；未证明自动预测、自动下发或押运排程。 |
| 用户反馈（预期体验） | “我希望一次看清明天各网点要多少现金，再结合库存和安全约束安排调配。” |
| 效率价值（V00） | 将每日次日申请集中汇总，需补每日准备人时、补报次数和处理截止时点。 |
| 质量/风险价值（V00） | 可减少漏报与版本混用，需补申请完整率、核对差错率及调运安全复核记录。 |
| 经营/管理价值（V00） | 有助匹配现金库存与网点需求，需补现金缺口、闲置库存和应急调运成本，不能承诺库存下降幅度。 |
| 数据范围 | 网点头寸使用申请、次日需求汇总；库存与调运约束为需补数据 |
| 输出 | 次日申请汇总、现金缺口与人工调配依据 |
| 人工确认 | 确认申请真实性、库存和调运安全约束，审定调配；需求异常先联系网点复核，资金不能自动转移。 |
| 协作与动作 | 当前为BI/程序案例基础，AI均为建议、非已实施能力。人工：确认申请真实性、库存和调运安全约束，审定调配；需求异常先联系网点复核，资金不能自动转移。 程序/规则：收集申请、按机构日期汇总和保留变更；库存匹配与阈值检查需补接口后验证。 分析模型：可建议预测现金需求，案例材料无预测模型。 大模型：建议解释缺口和整理调配理由，计算必须引用系统结果。 Agent：可建议汇总待审安排和提醒，不自动调拨、支付或安排押运。 |
