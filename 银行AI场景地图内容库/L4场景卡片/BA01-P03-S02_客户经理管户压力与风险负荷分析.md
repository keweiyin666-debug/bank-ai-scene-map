| 字段 | 内容 |
|---|---|
| 主业务域 | BA01 战略与经营管理 |
| L2 | BA01-P03 绩效与机构管理 |
| L3 | 无 |
| 主要使用角色 | 总行管理部门、分支机构负责人、客户经理 |
| 触发时点 | 每日监测、任务分配、客户移交、绩效辅导和风险集中度上升时 |
| 业务任务 | 汇聚借据与客户经理数据→规则计算压力→识别过载和集中风险→形成调配建议→人工评议 |
| 定义 | 管理者以多维管户压力和风险负荷识别客户经理过载与结构问题，辅助资源调配和绩效辅导。 |
| Before | 管理者只能看到客户经理“忙不忙”或结果指标，无法比较不同管户组合的复杂度和潜在风险。 |
| After | 系统按借据每日计算17个压力维度并展示构成，识别过载与集中风险，形成可解释的调配和辅导建议。 |
| 用户反馈（预期体验） | “我能说明压力来自哪些客户和风险结构，资源调整不再只看贷款规模或凭感觉。” |
| 效率价值（V00 待确认） | 按借据粒度每日更新17个压力维度，人工评估和任务分配时长目标待确认。 |
| 质量/风险价值（V00 待确认） | 识别客户、行业、担保和不良集中负荷，发现率和核查率目标待确认。 |
| 经营/管理价值（V00 待确认） | 服务总行、分支机构和客户经理3类角色，负荷均衡度目标待确认。 |
| 数据范围 | 贷款户数、用信金额、产品、担保、五级分类、逾期、投向、期限、利率和集中度。 |
| 输出 | 压力分、维度构成、风险集中点、过载预警、资源调配和辅导建议。 |
| 人工确认 | 确认权重阈值、过载原因、客户移交、资源安排和绩效辅导。 |
| 协作与动作 | 规则模型计算压力，Dora 解释构成并生成建议；人力和业务管理制度决定绩效、移交与资源安排。 |
| 实现范围 | 已有压力指标、配置表、存储过程和BI设计；人员调配闭环与管理效果待核实。 |
| 能力边界 | 压力值不是心理健康评估，不得脱离岗位和组合差异直接用于绩效处罚。 |
