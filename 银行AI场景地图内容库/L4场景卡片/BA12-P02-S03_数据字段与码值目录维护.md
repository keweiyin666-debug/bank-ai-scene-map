| 触发时点 | 数据上架、字段码值变化、主题更新与周期维护 |

| 定义 | 数据维护人员按主题登记和更新表字段及码值信息，供业务人员理解数据含义并复用授权数据资源。 |
| Before | 业务人员不易知道平台有哪些数据及字段含义，主题和码值解释分散，容易产生重复沟通和误用。 |
| After | 按业务主题登记字段与码值并提供查询，由维护人员定期更新；自动血缘、变更日志及全量治理范围需另行核实。 |
| 用户反馈（预期体验） | “我希望业务问到一个字段时能找到一致的定义和码值说明，修改后也知道该由谁确认。” |
| 效率价值（V00） | 集中查找字段与码值含义，需补查询解释和维护单项定义的耗时，不据目录规模推算节省人天。 |
| 质量/风险价值（V00） | 维护字段与码值2类说明，需补定义完整率、歧义率和更新及时率。 |
| 经营/管理价值（V00） | 支持业务复用统一定义，需补复用率、重复需求变化及责任覆盖率，当前没有已验证成效数字。 |
| 数据范围 | 数仓表、字段含义、业务主题、码值及数据责任信息（责任字段是否已有待核） |
| 输出 | 字段目录、码值说明、可复用数据主题与更新记录 |
| 人工确认 | 数据责任人确认定义与码值、批准变更；存在歧义先标待核，不让大模型自行填补口径。 |
| 协作与动作 | 当前为BI/程序案例基础，AI均为建议、非已实施能力。人工：数据责任人确认定义与码值、批准变更；存在歧义先标待核，不让大模型自行填补口径。 程序/规则：登记、分类、检索和展示字段码值；变更日志与一致性校验为建议控制，需补当前实现证据。 分析模型：核心维护不需要概率模型。 大模型：建议起草字段解释和发现疑似歧义，由数据责任人审核。 Agent：可建议组织待维护清单，不直接修改权威元数据或批准数据定义。 |
| 实现范围 | 字段及码值目录维护与查询；字段级血缘和影响传播不在本证据范围；当前AI与Dora部署未验证，AI等级仅描述建议设计。 |
| 能力边界 | 权威定义由责任人维护，不能与现有变更影响分析卡混同 |
